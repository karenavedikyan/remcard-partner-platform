## Как пользоваться без лишнего расхода контекста

Это reference book, не production-код. Сначала прочитай этот индекс. Файлы дальше отделены строками `## FILE: имя` и fenced code blocks. Извлеки нужные блоки локально обычным скриптом, затем читай только файлы этапа; не загружай всю книгу в контекст.

- Оболочка, тема и базовые формы: style.css и render() в app.js.
- Текущая команда: team-flex.js + team-flex.css. Они загружаются ПОСЛЕ team-v3 и заменяют wizard, роли, карточки и финальное сохранение.
- team-v3.css: базовая раскладка команды, mobile dialog, controls. team-v3.js: демо-данные и общие UI helpers. Старый фиксированный набор ролей/старый wizard из него НЕ являются финальным контрактом.
- Профиль, филиалы, обозначение будущего импорта: profile-v2.js/css.
- Канонические категории и их связи: taxonomy.js/css. Production taxonomy брать из API, не копировать demo-массивы.
- index.html фиксирует порядок подключения. lucide.js является библиотекой и не включён: используй существующие иконки/зависимости production.

## Что переносить, а что нет

Сохранить компоновку, иерархию текста, красный акцент, Manrope, светлую/тёмную тему, заметную CTA, 3 шага приглашения, таблицу прав, независимость должности/доступа, офис отдельно, выплаты отдельно от начисления.
Переиспользовать React/Next компоненты и реальные API. Не копировать глобальные переопределения функций, demo identity, example.invalid, in-memory persistence, fake accept/revoke, числовые счётчики и образцы финансовых сумм.
Числа 1000−600=400 иллюстрируют обязательства; это не мандат на новый банковский процесс или частичную оплату одного начисления.
«Перечислять» в данном прототипе означает согласованную область прав, не доказательство интеграции банка. Production CTA должно честно описывать фиксацию выполненного перевода.
Макет не вводит live-синхронизацию branch contacts с org, не обещает готовый Excel/1С, не меняет права владельца. При конфликте demo и правил безопасности руководствоваться заданиями серии.
