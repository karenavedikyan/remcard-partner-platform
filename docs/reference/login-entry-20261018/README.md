Владелец согласовал перенос страницы входа с неброской ссылкой «Администратору» и отдельным окном.

- Общий прототип: https://www.perplexity.ai/computer/a/1188b3fb-98d6-47aa-a1e6-39ea8bba10fd
- Архив: `prototype.tar.gz`, полный исходник принятой версии.
- SHA256 архива: `382c3faaf0daae2b8958915a7c6c060e4256a0ed71a2d58a5a835dc6c027260d`
- Локальный prototype git commit: `fe6daf3` (не SHA платформы).
- Production frontend base: `7376fb291ef67b6d5f763f8b3cf9917660606bfe`.

Распаковать архив в отдельную временную папку. Это эталон для просмотра, а не код для прямого копирования в production.

## Целевой путь

`roles.html` → «Войти» в верхней части welcome → «С возвращением» → MAX / Telegram → «Введите одноразовый код».

Внизу welcome и экрана «С возвращением» находится нейтральная ссылка «Администратору», открывающая модальное окно логина и пароля.

## Ограничения

- Переносим повторный вход `/login`, отдельный шаг OTP и вход администратора. Не переносим заново welcome/регистрацию, остальные кабинеты и демо-панели.
- Макет администратора намеренно не авторизует и очищает пароль. В реализации нужно использовать существующий рабочий admin auth, не демонстрационный обработчик.
- Демо OTP, тестовые значения, review toolbar, переключатель ролей и инструменты прототипа не переносятся.
- Неброская ссылка не является защитой: обязательна существующая серверная проверка прав.
- Нельзя менять backend, доставку MAX/Telegram, повторную регистрацию, logout/session semantics, production config/secrets/flags, lockfile policy.
- Только отдельная feature-ветка и PR; без merge/deploy и изменений release-веток.
