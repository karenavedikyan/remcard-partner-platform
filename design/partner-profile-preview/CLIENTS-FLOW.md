# Клиенты — предложение по потоку (прототип)

## Роли

- **Принимающий партнёр** сканирует сертификат клиента → создаётся обращение с привязкой к referrer, certificateId, скидке и контексту из сертификата.
- **Рекомендатель (referrer)** видит только свои исходящие обращения, сгруппированные по принимающим партнёрам и их текущим статусам — без редактирования и без служебных заметок.

## Статусы

1. Системные (не удаляются, не переименовываются): Новое обращение → … рабочие этапы … → Оплачено → Отгружено → (демо 14 дней «ожидает подтверждения» / «к подтверждению») · Возврат · Отказ с причиной.
2. **Рабочие этапы** настраивает каждый принимающий партнёр (Замер, КП, свои названия). Отображаются рекомендателю дословно.
3. **Отказ** доступен до оплаты; причины настраиваются (Цена / Сроки / Сортимент + свои).

## Дополнения прототипа

- **Добавить клиента** без сертификата (источник и контакт опциональны).
- Фильтр **источника** (скан / вручную / звонок / визит).
- Явные **демо-роли** актора: менеджер принимающего vs рекомендатель (только свои referral).
- **Оплачено** → ровно одна синтетическая **покупка** в read-only превью кошелька (отдельно от referral payout).
- После **Отгружено** — 14-дневное ожидание как в демо-кошельке (без новой машины подтверждений).
- Компактная **воронка** (создано → ever paid → ever shipped; возвраты отдельно).

## Открытые вопросы (не решены в прототипе)

- Полный vs частичный возврат и влияние на уже подтверждённое вознаграждение.
- Точная финансовая формула и момент «подтверждения» после 14 дней — только демо-текст, без выплат.
- Возврат: удержание/пересчёт не показаны.
