# Клиенты — предложение по потоку (прототип)

Статический демо-файл; зеркало для обсуждения с `clients-scenario-proposal.md` у владельца (локально на root).

## Две демо-перспективы (разные аккаунты)

Переключатель вкладок **не** имитирует один логин с двумя ролями. Это два подписанных демо-актёра:

| Вкладка | Строка контекста | Область данных |
|--------|------------------|----------------|
| Принимаю клиентов | **Демонстрация: принимающий партнёр …** | Только партнёр **A** (`DEMO-PARTNER-017` РемТех). Видны входящие от любых направивших, в т.ч. **D** (Андрей Ким). Не видны обращения у **C** (ФормаПро). |
| Отправил клиентов | **Демонстрация: направивший партнёр …** | Только **B** (`DEMO-PARTNER-0100` Мария Орлова). Видны её referral к **A** и **C**. referral **D**→A скрыты — это не «её» исходящие. |

Один и тот же объект обращения в памяти: смена статуса на вкладке A отражается у B для shared appeals. В проде — один текущий аккаунт, без смены перспективы и без просмотра чужих referral как своих.

**Настройки статусов** меняют только партнёра A; партнёр C в демо не затрагивается.

## Роли и скан

- **Принимающий** сканирует сертификат → обращение с referrer, certificateId, скидкой, контекстом.
- **Повторное сканирование** в демо открывает только **активное** обращение (не «Отказ» / не «Возврат») у того же принимающего.
- Повторная покупка по сертификату **после закрытой сделки** — **не решено**; демо не обещает правило «один сертификат = одно обращение навсегда».

## Статусы

1. Системные: Новое → рабочие этапы → Оплачено → Отгружено → (кошелёк) · Возврат · Отказ.
2. Рабочие этапы настраивает каждый принимающий (видны направившему дословно).
3. **Оплачено** — одна синтетическая **покупка** в read-only кошельке (≠ referral payout).

## 14 дней после отгрузки (предложение для согласования)

После **Отгружено** в демо-кошельке: **14 календ. дней ожидания** для referral, затем фаза **«К подтверждению»**.

- **«К подтверждению»** — **не** автоматическая выплата; решение **на согласовании с владельцем продукта**.
- Покупка клиента и реферальное вознаграждение разделены.

## Открытые вопросы

- Полный/частичный возврат vs уже прошедшее ожидание referral.
- Повторная сделка по тому же сертификату после закрытия.
- Удержания при возврате.
