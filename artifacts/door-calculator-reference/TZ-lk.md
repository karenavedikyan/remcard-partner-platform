# ТЗ: калькулятор дверей в кабинете партнёра (ctx=lk)

Контекст. Сайт-версия калькулятора уже сделана и принята в репозитории remcard-navigator (ветка cursor/remcard-d3b4, коммит eda0a1e0): код лежит здесь как эталон в `backend-code/` (чистый модуль `src/lib/doorCalculator`, мастер `src/components/doorCalculator`, страницы), отчёт — `backend-REPORT_RU.md`. Эталон дизайна и поведения — прототип `prototype/door-calc/wizard.html?ctx=lk` (запуск: `python3 -m http.server` в папке `prototype`, затем открыть `/door-calc/wizard.html?ctx=lk`), скриншоты `prototype/door-calc-lk-desktop.png`, `door-calc-compare-*.png`. Сценарии: `prototype/FLOWS.md`.

## Задача
Добавить калькулятор дверей в кабинет партнёра (prof.remcard.ru) для расчёта заказов своих клиентов.
1. Перенеси без изменений логики модуль `src/lib/doorCalculator` (calc, compare, constants, modelSource, offer, types) и его юнит-тесты. Результаты расчёта должны совпадать с эталоном до рубля; тесты паритета обязательны (те же фикстуры: 900×2050×250 + 800×2050×120, Скандинавия 01 из DEMO_DOOR_MODELS, скидка 10 % → 49 050 / 44 145 / выгода 4 905).
2. Перенеси мастер (4 шага, 3D-проём, сравнение моделей до 4, спецификация с ценами в строках, скидка, блок «Ваши данные») и страницу предложения, адаптировав под оболочку кабинета (AppShell, стили кабинета/прототипа ctx=lk, шапка без хлебных крошек сайта; выход по крестику ведёт в кабинет). Страница, например, `/doors-calculator` и `/doors-calculator/offer`.
3. Пункт меню «Калькулятор дверей» (иконка двери) в десктопной навигации COMPANY_DESKTOP_NAV и STORE_DESKTOP_NAV (`src/lib/business-nav/sections.ts`), показывать только организациям типа компания/магазин, у которых среди выбранных направлений/категорий есть «Двери» (найди, как категория хранится и приходит во фронт: см. profile directions, `src/lib/partner-directions`, `GET /api/pro/context`/профиль; не придумывай новые поля API, если данных достаточно). Без категории «Двери» пункта нет и прямой переход на страницу показывает нейтральное сообщение «Раздел недоступен для вашего профиля» без расчётов. Не расширяй права сотрудников: пункт и страница доступны тому же кругу, который уже видит остальные рабочие разделы организации; новых прав не вводить.
4. Телефон: в нижней панели места нет. Сделай отдельную строку-вход «Калькулятор дверей» на главной кабинета (над блоком разделов/каталога, как на `door-calc-lk-desktop.png` и в прототипе на телефоне), только при тех же условиях.
5. PDF-предложение: подставляй логотип, название компании, телефон, мессенджер, e-mail, сайт, адрес из профиля организации (то, что уже есть в кабинете/публичных контактах); если поля пустые, не показывай их. В боковой панели «Профиль партнёра» предложения значения предзаполнены и редактируемы только в этом предложении, в профиль ничего не записывается.
6. Каталог: используй тот же `DoorModelSource`; на проде источник пустой, режим «Из каталога» скрыт, ручной ввод моделей и цен полностью работает. Демо-модели в прод не попадают.

## Ограничения
- Расчёт на клиенте, без новых API, миграций, таблиц и записи данных. Никаких автоматических PR, деплоя, работы с реальными данными.
- Не менять существующие разделы, права, финансовые правила, сценарии приглашений, сертификатов, сканирования, кошелька.
- Тесты: паритет расчёта, видимость пункта (компания/магазин с «Двери», без «Двери», мастер/агент/сотрудник), страница без категории, мобильный вход, сравнение моделей (добавление, удаление, лимит 4, сброс при смене проёмов).
