# ТЗ Cursor: каталог товаров партнёра в кабинете prof.remcard.ru (репозиторий remcard-partner-platform)

Роль этого репозитория: интерфейс кабинета. Данные и API делаются в другом репозитории (remcard-navigator) параллельно по контракту ниже. Пока API нет в проде, строй типизированный клиент и мок-источник на фикстурах «Оптовик» (из прототипа) и подключай реальный API за флагом.

## Что сделать
1. Раздел «Каталог» в боковом меню, вкладка «Товары» (образец: `partner/product-catalog.js`, вкладки по прототипу, `open=goods`). Показ владельцу и сотруднику с правом catalog; сотруднику без права раздела нет.
2. Панель фильтров по свойствам 1С слева, поиск, сортировка, карточки/список, групповые действия (показать, скрыть), полноэкранный режим, состояния модели («На сайте», «Скрыт вами», «Нет фото», «Нет цены»). Правила фильтра как в общем разделе выше. Образец: `client/catalog-lk.js`, `partner/product-catalog.js`.
3. Карточка товара кабинета: публикация, филиалы, цена по филиалам (правило филиала или своя цена), остаток по режиму; закупка, наценка и вкладка «Филиалы и цены» только владельцу (низкая наценка меньше 25 процентов подсвечивается). Сотруднику эти поля не отображаются и в ответ не приходят.
4. «Вид на сайте»: предпросмотр страницы продавца как её видит клиент, без закупки и наценки.
5. Калькулятор дверей `/doors-calculator`: реальный `DoorModelSource` («Из каталога») из каталога своей компании; пункт меню «Калькулятор дверей» оставить; переносить калькулятор внутрь заявок не нужно (этап 2).
6. Не делать вкладки «Заявки», «Поставщики» и статус поставщика (этапы 2 и 3).

## Критерии приёмки
- Экраны 1:1 с прототипом на 1386x719, 1460x833 и 390x844, обе темы; расхождения перечислены.
- Сотрудник: нет закупки, наценки, вкладки «Филиалы и цены» ни в DOM, ни в ответах; владелец: всё есть.
- Смена организации или филиала не показывает старые данные; ошибка филиала не блокирует остальные действия и не путается с «филиал не выбран».
- Флаг выключен: кабинет как на проде (регрессия).
## Что делаем (этап 1 из 3)

Каталог товаров партнёра из 1С. Пример в прототипе: «Оптовик», двери и фурнитура. Эталон вида и поведения: прототип в `artifacts/catalog-reference/prototype/` (запуск: `python3 -m http.server` в этой папке, затем `index.html`, карточки «Каталог партнёра из 1С» и «Калькулятор дверей»). Прототип HTML и переносить как есть нельзя: нужно реализовать в React-компонентах репозитория, но экраны, тексты, порядок элементов, правила фильтров и состояния должны совпадать с прототипом точно. Любое расхождение, которое ты считаешь необходимым, перечисли в отчёте, сам не придумывай.

Этап 1 (эта задача):
1. Каталог на сайте клиентов remcard.ru: вкладка «Товары» на странице продавца, фильтры, поиск, сортировка, карточка товара с блоком «Где купить».
2. Кабинет партнёра prof.remcard.ru: «Каталог → Товары», управление публикацией (показ на сайте, филиалы, цены по филиалам), закупка и наценка только владельцу, предпросмотр «Вид на сайте».
3. Калькулятор дверей: режим «Из каталога» берёт модели из опубликованного каталога партнёра и считает расчёт (сайт и кабинет). Режим «Вне каталога» остаётся как есть.

Этапы 2 и 3 (НЕ делать сейчас, не начинать, не готовить заглушки в интерфейсе): 2 — заявки клиентов продавцу с перепиской через RemCard и боты, сертификат в заявке, «Расчёт по дверям» и «Отправить клиенту» внутри заявки; 3 — вкладка «Поставщики», заявка на статус поставщика, модерация в админке.

## Данные из 1С (контракт)

- Источник — снимок номенклатуры 1С (JSON). Позиция: guid, name, chapter (раздел), guid_group/name_group (группа), properties (свойства 1С с исходными названиями), files (guid файла, название, относительный путь), цены по типам цен, остаток.
- Идентичность товара: компания + система-источник + guid позиции. Повторная загрузка обновляет запись, дубли не создаёт.
- Название, цена и остаток приходят из 1С и в кабинете не редактируются. Партнёр управляет только показом на сайте, филиалами и ценой по филиалам.
- Публичные типы цен: «РРЦ Тандор» и «АкционнаяЦена_Тандор_Розница». Остальные типы (АкционнаяЦена_Тандор_ОПТ, Минимальная, Минимальная Осауленко, Минимальная Ростов, Эксклюзив Тандор) внутренние и клиенту, сотруднику и сайту не отдаются.
- Закупочная цена и наценка видны только владельцу организации. Сотрудники, клиенты, публичный API и предпросмотр их не получают. Права сотрудников не расширять: пункт «Каталог» у сотрудника только при праве catalog, как в прототипе.
- Остаток: режимы «Статус: В наличии или Под заказ», «Точное количество», «Не показывать». Неизвестный остаток не равен нулю.
- 24 свойства фильтра с исходными названиями (не склеивать похожие): Цвет, Цветовая гамма, Покрытие, Покрытие двери, Материал, Дизайн, Вид двери, Размер мм, Высота, Длина, Толщина, Толщина полотна мм, Толщина стали мм, Сторона открывания, Тип товара, Тип погонажа, Тип фурнитуры, ВХ. Терморазрыв, ВХ. По назначению, ФР. Вид ручки, ФР. Основание ручки, ФР. Тип установки, ФР. Тип замка, ФР.Стиль.
- Правила фильтра (как в client/catalog-lk.js прототипа): значения одного свойства — «или», разные свойства и прочие ограничения — «и»; все условия проверяются на одной позиции 1С (модель подходит, если подходит хотя бы один её вариант); в списке значений только реально имеющиеся; поиск без учёта регистра и ё/е, по всем словам запроса (название, артикул, бренд, раздел, свойства); пустое свойство не равно «Нет»; счётчики различают модели и подходящие варианты.
- Состояния модели в кабинете: «На сайте», «Скрыт вами», «Нет фото», «Нет цены». Модель без фото или без цены на сайт не попадает.
- Фото: только клиентские производные (миниатюры 240/640), без служебных адресов хранилища и доступов; без фото — нейтральная заглушка; вписывать целиком, не обрезать.

## Калькулятор «Из каталога»

В коде есть шов `src/lib/doorCalculator/modelSource.ts` (`DoorModelSource`, сейчас `emptyDoorModelSource`, режим скрыт). Нужно:
- реальный источник моделей: опубликованные двери компании (на сайте — продавец, чей калькулятор открыт или «Оптовик» по умолчанию; в кабинете — каталог своей компании), модель = группа вариантов 1С; название, производитель, цвет, цена «РРЦ» за полотно, размеры полотен (`blades`) из свойств 1С; доборы, коробка, наличник и фурнитура — если есть в каталоге, иначе цены вводятся вручную как сейчас;
- если у публичного каталога нет моделей дверей, режим «Из каталога» скрыт, как сейчас;
- выбор модели «Из каталога» или «Вне каталога», подстановка цен «подставлены из каталога, можно изменить», сравнение моделей, скидка, итог и PDF предложения работают как в прототипе; расчёт остаётся на клиенте и совпадает с текущим по формулам (формулы не менять);
- принцип калькулятора: «что ввели, то и получили»; данные либо из каталога, либо вручную; цены вне каталога разрешены.

## Общие правила

- Автоматический PR и деплой запрещены: только коммиты в ветку, с которой стартуешь. Миграции БД писать файлами, НЕ применять. Реальные данные 1С и прод не использовать: только фикстуры и сид для тестов. Каталог за флагом (по умолчанию выключен), прод не меняется до отдельного решения владельца.
- Не менять приглашение партнёра, создание сертификата, сканирование, кошелёк, права и существующий расчёт.
- Тесты: свои на каждый пункт приёмки (фильтры, права владельца и сотрудника, скрытие закупки, публикация, калькулятор), `npx tsc --noEmit`, `npx next build`, vitest по затронутым областям. Скриншоты 1386x719, 1460x833 и 390x844, светлая и тёмная тема, каждого нового экрана рядом со скриншотом прототипа в `artifacts/catalog-reference/out/`.
- В каждом коммите трейлер `Co-authored-by: Perplexity <noreply@perplexity.ai>` ровно один раз. В конце: точный SHA, таблица «пункт, что сделано, тест», список расхождений с прототипом, список того, что требует миграции или отдельного разрешения.
